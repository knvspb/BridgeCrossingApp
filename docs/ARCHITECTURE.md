# Архитектура BridgeCrossingApp

## Цепочка модулей

```
Журнал работы студентов → Варианты проекта → Расчёт уровня воды → Определение отверстия моста
                                                → Проектирование регуляционных сооружений → Вариантное проектирование моста
                 ↑
        Генератор задания (этот этап)
```

Все модули связаны одним объектом — **вариантом задания** (JSON). Генератор его создаёт, остальные модули только читают и добавляют свои результаты в отдельные разделы (например, `results.waterLevel`). Исходные разделы варианта они не меняют.

## Принципы

1. **Модульность без сборки.** Каждый модуль — отдельная страница `apps/<модуль>/index.html`. Общий код лежит в `core/` и подключается обычными `<script>`, без бандлера и ES-модулей. Поэтому страница открывается двойным щелчком (file://), с GitHub Pages и без интернета. Те же файлы подключаются в Node.js для тестов (`tests/load.js`).
2. **Ядро без интерфейса.** Расчёты и генераторы в `core/` — чистые функции над объектом варианта. Интерфейс только вызывает их и рисует.
3. **Выгрузка в редактируемые форматы на каждом этапе.** Общий сервис `core/export.js` (ExcelJS, CSV, JSON). Расчётные листы выгружаются с **живыми формулами Excel** и посчитанными значениями: это нужно для прямой математической проверки студенческих работ.
4. **Истина и то, что видит студент, разделены.** В варианте хранятся истинные значения: отметки дна, УВВ на оси перехода, ВИУ, уклон. Студенческое представление вычисляется: глубины от уровня на дату изысканий, превышения над нулём поста, ВИУ над известным объектом, уклон по двум урезам, перенос с водпоста. Модуль «Журнал» по истинным значениям проверяет ответы студента.
5. **Воспроизводимость.** Все генераторы детерминированы зерном (`meta.seed` и производные). Вариант можно восстановить по зерну и параметрам.

## Структура каталогов

| Путь | Назначение |
|---|---|
| `index.html` | Стартовая страница со списком модулей |
| `apps/generator/` | Генератор задания (этап 1) |
| `apps/…` | Будущие модули: journal, variants, water-level, opening, regulation, bridge-variants |
| `core/bca.js` | Пространство имён `BCA`, утилиты, ГСЧ (mulberry32, нормальное, гамма, Пирсон III), гладкий шум |
| `core/schema.js` | Схема варианта, значения по умолчанию, миграции, автозаполнение, проверка, разделы шаблонов |
| `core/profile.js` | Профиль по створам, перестроение по ширинам и шагам, генераторы рельефа и ИГУ, глубины |
| `core/hydraulics.js` | Живое сечение по зонам и кривая Q(Z) (шаги 0–1 спецификации расчётной книги) |
| `core/hydrology.js` | Синтетические ряды уровней, таблица превышений, таблица для РСУ, студенческое представление |
| `core/topo.js` | Пространственная топоповерхность и облако точек CSV |
| `core/export.js` | Excel (бланк задания, ключ с формулами, суточные уровни, столбец старой книги), CSV |
| `core/charts.js` | SVG: профиль с ИГУ и уровнями, годовые гидрографы (только браузер) |
| `core/soils.js`, `core/catalogs.js` | Справочники: 44 грунта, ландшафт/шероховатость, типы рек, категории дорог |
| `vendor/exceljs.min.js` | ExcelJS 4.4.0 (MIT), локальная копия |
| `tests/` | `node --test tests/*.test.js` |

## Вариант задания (schemaVersion 1)

```text
meta      шифр, № варианта, студент, группа, дисциплина, преподаватель, сроки, seed
tz        категория дороги, полосы, отметки ПЧ, ответственность, район, вероятность p, класс судоходства,
          axisPoints — характерные точки оси дороги на подходах
geodesy   stepLP / stepR / stepPP, z[] (все створы), iL / iR (бровки), surveyLevel (уровень на дату изысканий =
          ноль измерения глубин), comments{}
hydro     unm; post {zero, offsetKm, nYears, firstYear}; viu {z, year, refName, refZ};
          slope {i, studentMode, Lkm}; morph {LP, R, PP: {id, m, text}};
          regime {feed, landscape, iceJams, zLo, zHi, Cv, CsCv, navMean, navSd};
          rsuT[], rsuConsecutive; wind {v, fetch};
          series[] {year, zMax, dMax, navStart, navDays, jam, daily[365]} — уровни на оси перехода
geology   ubv (условный низ), corr, seed, layers[] {no, code, tops[], gen}
topo      radius, gridStep, size, amp, seed
gen       параметры генератора профиля
library   справочник шероховатости (редактируемый, сохраняется с вариантом)
```

Число створов производное: `n = ширина / шаг` по каждой зоне. Разбиение 30 + 10 + 30 интервалов (71 створ) совместимо со старой Excel-книгой: для него доступна выгрузка столбца варианта (строки D5…D968).

При изменении структуры нужно увеличить `SCHEMA_VERSION` и дописать шаг в `schema.migrate()`. Старые файлы должны открываться.

## Шаблоны

Можно сохранить всё задание или отдельные разделы с уникальным именем:

| Раздел | Состав |
|---|---|
| `geodesy` | Геодезические изыскания и промеры: профиль, шаги, параметры генератора, топография |
| `hydro` | Гидрометеорологические изыскания и справочник шероховатости |
| `geology` | Геологические изыскания |
| `tz` | Данные технического задания |

Шаблоны хранятся в `localStorage` браузера; для переноса на другой компьютер их можно экспортировать и импортировать JSON-файлом.
